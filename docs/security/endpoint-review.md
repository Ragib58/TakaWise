# Endpoint Security Review (Phase 7)

> 2026-11-06 · Scope: every route under `/api/v1`. The inventory is **enforced by a test**: `apps/api/test/security/route-inventory.e2e-spec.ts` lists every registered route and fails if any route outside the public allowlist answers without a valid access token.

## Cross-cutting controls

| Control                     | Implementation                                                                                                                                                                                                                    | Evidence                                                    |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Default-deny authentication | Global `JwtAuthGuard`. Each request also checks that the session is live and the user is ACTIVE                                                                                                                                   | route-inventory test (all ~70 routes)                       |
| Identity from token only    | `@CurrentUser()`. Strict Zod bodies and queries reject `userId` and any unknown key                                                                                                                                               | auth, ledger and planning flow tests                        |
| Ownership                   | Every query on owned data includes `userId`. Foreign ids return 404. Composite `(id, user_id)` FKs and triggers in SQL                                                                                                            | IDOR suites in the ledger, planning, reports and auth tests |
| Validation                  | Zod contracts shared with the web app; money as decimal strings; bounded ranges and page sizes                                                                                                                                    | contract and unit tests                                     |
| Idempotency                 | `Idempotency-Key` required on all financial commands; stored in the same transaction                                                                                                                                              | ledger and planning tests, incl. concurrency                |
| Rate limiting               | 120/min per client globally; 10/min on login, verify, refresh and reset; 5/min on email-sending routes; 10/min on export. Counters live in Redis and are shared across instances, with a per-instance fallback when Redis is down | `rate-limit-redis.int-spec.ts`                              |
| CSRF                        | Cookie routes (`refresh`, `logout`) require an allowlisted Origin plus a double-submit `X-CSRF-Token`. Every other route uses a bearer token                                                                                      | auth flow tests                                             |
| CORS                        | Explicit origin allowlist with credentials; production refuses default origins                                                                                                                                                    | env and e2e tests                                           |
| Headers (API)               | helmet: HSTS, nosniff, frame protection, `Referrer-Policy: no-referrer`, CSP (Swagger disabled in production)                                                                                                                     | `hardening.e2e-spec.ts`                                     |
| Headers (web)               | CSP (`default-src 'self'`, no third-party scripts, `connect-src` = API origin, `frame-ancestors 'none'`), HSTS, COOP, Permissions-Policy                                                                                          | `next.config.ts`, smoke test                                |
| Body limits                 | JSON and form bodies limited to 100 kB; oversize returns 413                                                                                                                                                                      | e2e test                                                    |
| Logging                     | pino with redaction (auth headers, cookies, passwords, tokens, codes, notes, descriptions). URLs are logged without query strings. Prisma errors are logged by class and code only, never the message                             | `hardening.e2e-spec.ts`                                     |
| Errors                      | One envelope; internal messages are never returned to clients                                                                                                                                                                     | e2e test                                                    |
| Metrics                     | `/metrics` needs `METRICS_TOKEN`; it is hidden (404) in production without one; labels use route templates only                                                                                                                   | `hardening.e2e-spec.ts`                                     |
| Uploads                     | **No upload endpoint is exposed in the MVP.** The `files` table and `/files/presign` are reserved for v1.1 receipts, which will need signed URLs plus MIME, size and content checks                                               | route inventory                                             |

## Public routes (allowlist)

| Route                                                                       | Why public           | Extra protection                                                                                                                      |
| --------------------------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/register`, `/auth/resend-verification`, `/auth/forgot-password` | pre-login            | 5/min. Identical responses (no account enumeration). Password policy                                                                  |
| `POST /auth/verify-email`, `/auth/login`, `/auth/reset-password`            | pre-login            | 10/min. Codes are HMAC'd, expiring, single-use and allow 5 attempts. Timing parity on login                                           |
| `POST /auth/refresh`, `/auth/logout`                                        | cookie-authenticated | CSRF (Origin + double submit). Refresh rotation with family reuse detection                                                           |
| `GET /health`, `/health/ready`                                              | orchestrator probes  | no data. Readiness reports dependency status only                                                                                     |
| `GET /metrics`                                                              | Prometheus scrape    | bearer `METRICS_TOKEN`, or 404 in production                                                                                          |
| `POST /billing/webhooks/:provider` (Phase 10)                               | payment provider     | HMAC-SHA256 over the raw body with timestamp (±5 min); only the configured provider (404 otherwise); idempotent per event id; 120/min |

## Known residual risks

- **Staff accounts have no MFA yet (Phase 10).** Do not grant ADMIN in production until MFA exists (launch checklist #14).
- **No real payment gateway.** The webhook verifier is generic HMAC; a real provider adapter must implement that provider's own signature scheme.

- **Web CSP allows `'unsafe-inline'` scripts.** Next.js App Router hydration emits inline scripts. No third-party script origin is allowed, and no user content is rendered as HTML (React escapes all output). The upgrade path is nonce-based CSP via middleware, which makes pages dynamic, and is planned before public launch.
- **Access token in memory and refresh cookie set to SameSite=Strict:** an XSS could still call the API while the tab is open. The mitigations are CSP, React escaping, no HTML rendering of user content, and a 15-minute access-token lifetime.
- **No MFA yet.** The settings page states that it is coming.
- **Bangla/English copy and the privacy/terms drafts** need native-speaker and legal review (launch checklist).
- **AI provider data processing (Phase 9).** With `AI_PROVIDER=anthropic`, consented aggregates and, for drafts and OCR, the typed sentence, the receipt image, and account and category names go to the provider. The provider's terms, retention and region, and the AI notice text, need legal review before AI is enabled in production. Prompt injection is mitigated in layers (untrusted blocks, schema-constrained output, re-validation, no tools, review before save) but is not impossible. The worst outcome is a misleading draft or sentence shown to the same user.
